# Architecture

## Layers

### Aether Core

Core owns structured graph state, validated commands, branches and merge state, proposals and approvals, simulation interfaces, audit events, capability state, persistence, and recovery.

### Architecture Lab

Architecture Lab defines services, databases, queues, gateways, regions, traffic routes, dependencies, SLOs, capacity, cost, and failure scenarios. Its validators and simulation rules are domain-specific.

## Command pipeline

```text
Human gesture or WebMCP invocation
  -> typed command validation
  -> authorization and policy gate
  -> domain validation
  -> branch mutation
  -> event/audit record
  -> canvas and capability update
```

No caller receives a privileged mutation path.

## Core records

- `Workspace`: domain type, participants, active branch, timestamps.
- `GraphEntity` and `GraphRelationship`: typed objects, properties, positions, and versions.
- `Branch`: immutable base revision, ordered operations, derived graph, validation and simulation state.
- `Proposal`: change set, rationale, affected entities, impact preview, lifecycle status.
- `AetherEvent`: command, sanitized input/output, actor type, branch, and timestamp.
- `SimulationRun`: snapshot hash, scenario, engine version, metrics, violations, and result status.

## Deterministic boundary

Language models are probabilistic: intent understanding, tool selection, proposal generation, and evidence explanation. The command engine, branch DAG, simulation engine, diffing, approval eligibility, merging, and rollback are deterministic.

Each simulation must be reproducible from `snapshotHash + scenario + engineVersion`. Metrics are never generated by a model.

## Expansion rule

New domains implement a schema, validators, scenarios, and simulator behind the Core interfaces. They must not alter the shared command, proposal, approval, audit, or branch semantics.
